# DSH Desktop 统一智能工作台需求说明

## 1. 目标

DSH Desktop 在现有 DeepSeek Harness 会话、技能和知识库能力之上，提供统一的桌面工作入口。用户应能在不打断当前会话的情况下切换工作模式、查看上下文来源、浏览网页、加入本地文件，并为代码任务创建 Git 隔离工作区。

## 2. 用户与场景

- 普通用户：通过对话、文件和网页完成资料分析与内容工作。
- 开发者：在本地工作区执行代码任务，调用技能和子智能体，并用 Git Worktree 隔离并行任务。
- 知识工作者：使用知识库、Obsidian、长期记忆和网页内容获得有来源的回答。

## 3. 功能需求

### FR-01 统一入口

- 主窗口顶部提供固定的 DSH Desktop 工具栏。
- 工具栏统一承载模式、文件、浏览器、上下文和 Git 隔离入口。
- Harness 原有左侧工作区、会话、技能、知识库菜单完整保留。
- 打开工具面板或浏览器时，不销毁、不刷新当前会话。

### FR-02 快捷呼出

- 默认全局快捷键为 `CommandOrControl+Shift+D`。
- 快捷键在主窗口隐藏、最小化或被其他应用遮挡时恢复并聚焦窗口。
- 再次触发时保持当前会话、浏览器和上下文状态。
- 应用菜单提供同名入口，快捷键注册失败不得阻止客户端启动。

### FR-03 工作模式

- 提供“对话”和“工作”两种明确模式。
- 对话模式偏向解释、讨论和信息整理，在需要时才执行工具。
- 工作模式偏向自主完成、验证和交付任务。
- 模式选择持久保存，并在每轮请求前作为客户端上下文注入模型。
- 模式切换不重启服务、不清空会话。

### FR-04 文件拖放

- 用户可将一个或多个文件拖放到顶部文件入口。
- 客户端取得本地绝对路径，将文件清单插入当前会话输入框。
- 文件来源同步显示在上下文面板中，最多保留最近 8 项。
- 不自动上传文件到第三方服务；实际读取由当前 Agent 和权限策略决定。

### FR-05 内置浏览器

- 浏览器作为主窗口右侧分栏打开，Harness 会话仍保持可见和运行。
- 支持输入地址、搜索关键词、后退、前进、刷新和关闭。
- 只允许 `http`、`https` 页面；网页不获得 Node.js 权限。
- Harness 中点击的外部链接默认进入内置浏览器。
- 用户可主动把当前网页加入上下文；客户端采集标题、URL、选中文本或有长度上限的正文摘要。

### FR-06 可见上下文来源

- 上下文面板列出当前模式、`DSH.md`、`memory.md`、话题记忆、技能、知识库、最近文件、已引用网页和 Git 隔离工作区。
- 每项显示启用状态、数量或文件大小，用户可刷新。
- 网页正文属于不可信参考资料，不得作为系统指令执行。

### FR-07 DSH.md 与分层记忆

- 每个会话优先读取 `~/.dsh/DSH.md`。
- `memory.md` 保存简短经验，超过 8 KiB 后按话题拆入 `~/.dsh/topics/*.md`。
- 话题文件只在当前问题匹配相应话题时加载。
- 新建工作区使用项目级 `DSH.md`，兼容读取已有 `AGENTS.md` 和 `CLAUDE.md`。

### FR-08 按需技能与生命周期

- 会话开始只提供技能索引，技能正文在匹配或调用时加载。
- 用户明确输入“记住……”时，在模型回答前持久化。
- 可复用的一句话经验写入记忆，多步骤经验写成 Skill。
- 桌面模式、网页和文件上下文在 Agent 每轮执行前注入。

### FR-09 子智能体

- 标准、PTC 和创造模式保留 `spawn` 与 `fork` 子智能体。
- 支持前后台运行、查看层级、继续、停止和结果回传。
- 桌面壳层不得拦截或刷新子智能体会话。

### FR-10 Git 隔离

- 用户可选择一个 Git 仓库并输入任务名称。
- 客户端基于当前 `HEAD` 创建独立分支和 Git Worktree。
- Worktree 放在 `~/.dsh/worktrees/`，创建结果加入上下文并插入当前输入框。
- 用户可在系统文件管理器中打开 Worktree。
- 删除操作只允许清理无未提交变更的 Worktree，并要求用户在界面中确认。

### FR-11 一键目录知识库

- 知识库页面提供“从目录创建”主入口；用户只需选择一个本地目录，无需先手工创建知识库或逐个上传文件。
- 客户端递归扫描目录内的 PDF、Word（`.docx`）、Markdown 和纯文本文件，自动转换为 Markdown、切片并建立本地检索索引。
- 默认以所选目录名作为知识库名称，文档列表保留相对目录结构；隐藏目录、符号链接和不支持的文件不进入索引。
- 再次选择同一目录时同步原知识库，反映新增、修改和删除的文档，不重复创建知识库。
- 单文件限制 20 MB，单目录最多 1,000 份可导入文档且总大小不超过 100 MB；完成后显示成功、跳过和失败文件摘要。
- 普通目录知识库与 Obsidian Vault 分类建库并存，均可保存为全局或当前项目知识库，并参与会话自动检索。

## 4. 非功能需求

- 支持 macOS、Windows 和 Linux；平台差异封装在 Electron 主进程。
- Harness 服务只监听 `127.0.0.1`。
- 浏览器、Harness 和桌面壳均启用上下文隔离，禁用远程页面 Node.js 能力。
- 文件、网页正文和上下文数据设定数量与长度上限。
- 所有持久状态保存在 `~/.dsh`，不覆盖用户已有指令和记忆。
- 默认工作区使用 `~/.dsh/workspaces`，首次启动不依赖操作系统的“文稿”目录权限。
- 新功能失败时应局部降级，不能导致会话服务退出。

## 5. 验收标准

1. 启动后可见统一工具栏，Harness 左侧菜单和当前会话可正常使用。
2. 全局快捷键可恢复并聚焦主窗口。
3. 对话/工作模式可切换、持久化，并出现在上下文来源中。
4. 拖入文件后，当前输入框出现路径清单。
5. 内置浏览器可分栏导航；加入上下文后可见网页标题和 URL。
6. 上下文面板正确统计指令、记忆、话题、技能和知识库。
7. `DSH.md`、记忆拆分、按需技能和“记住”机制继续通过原测试。
8. 标准模式的子智能体工具与会话树仍在运行时中。
9. Git 仓库可成功创建独立 Worktree，非 Git 目录给出清晰错误。
10. 自动测试、嵌入服务冒烟测试和实际桌面启动通过。
11. 选择含多级子目录和混合文档格式的目录后，系统自动创建一个可检索知识库；再次选择同一目录可原位同步。
